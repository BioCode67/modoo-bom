## 0. 주제 적합성 — ✅ 정면 부합 (그러나 서사를 명확히)

"복지"는 라이프스타일의 근간이고, 모두봄은 **찾기→이해→행동(신청)→사후관리**를 에이전트가 대행하는 구조라 주제와 정면으로 맞는다.
단, "AI Agent"의 정의를 발표에서 선점해야 한다: **인지(프로필·상황) → 판단(자격·우선순위) → 행동(담기·서류발급·신청) → 관찰(마감·갱신 감시)의 자율 루프**. 챗봇이 아니라 이 루프 전체가 에이전트다.

## 1. 기준별 냉정 채점 (10점 만점 자체평가)

|---|---|---|---|

| 개인화 방식 | 로그인+공적정보 | 서버 프로필 | **온디바이스(서버 전송 0)** |

### 기술성 30 — 자체 8/10 (오늘 보강함)
- **최대 리스크였던 것**: 주제가 'AI Agent'인데 라이브 데모의 챗·판정이 규칙 엔진 → "이게 AI인가요?" 공격.
- **오늘 해소**: 챗 **하이브리드 승격** — 백엔드 연결 시 지식 질문은 **진짜 LLM(Claude, /ws/chat)**, 행동(담기·서류·자격)은 로컬 에이전트, 실패 시 규칙 폴백. 화면에 정직 라벨.
- 기술 스토리 3층: ①온디바이스 신경망(multilingual-e5, 브라우저 실행) ②LangGraph 10노드+Claude(클라우드/로컬) ③**지능형 RPA**: 진짜 크롬+CDP로 정부24 안티봇(Mbuster) 통과 + **화면(DOM+비전)을 읽고 다음 행동을 LLM이 판단**하는 관찰-판단-실행 에이전트(browser-use/Skyvern 계열의 '결정 계층'을 우리만의 '안티봇 통과 실행 계층' 위에 얹음) → **처음 보는 서류·사이트도** 발급 흐름을 스스로 탐색. 검증된 8종은 결정적 경로(하이브리드).
- **본선 필수 액션**: Render에 백엔드 상시 배포(DEPLOY_CHECKLIST) → 심사장에서 "🧠 실시간 AI" 라벨이 보이게. 로컬 규칙 폴백이 있으니 데모 리스크 없음.

## 2. 예상 공격 질문 Top 5 & 답변

1. **"복지로랑 뭐가 달라요?"** → 비교표 + "민간재단·온디바이스·신청 실행" 3단 답.
2. **"AI가 어디 쓰였죠? 규칙 기반 아닌가요?"** → 3층 구조(온디바이스 신경망/LLM 하이브리드/규칙 폴백) + "행동은 기기 안, 지식은 LLM, 실패해도 동작" — 폴백은 결함이 아니라 신뢰성 설계.
3. **"자동 신청이 다 된다고요? 법적 문제는?"** → "본인인증·최종 제출은 설계상 사람 몫(human-in-the-loop). 무인 대행은 하지 않으며 그게 옳다" — 정직성이 방어가 됨.
4. **"데이터 최신성은?"** → ETL 재수집 파이프라인 + 시드 실측 검증 프로세스(복지로 ID 재배정 사건 사례로 답하면 강함).
5. **"수익모델/지속성?"** → 공공 제휴(지자체 보급)·재단 제휴, 운영비 최소(정적+온디바이스).
