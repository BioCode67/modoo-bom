# 7/20(월) 코드 제출용 — 게시글/코멘트 초안

> 코드 제출은 "github 링크로 대체 가능". 링크만 던지지 말고, 심사위원이 10분 안에
> 실동작을 재현할 수 있는 경로를 함께 적는 게 구현완성도 점수에 직결된다.

**소스**: https://github.com/BioCode67/modoo-bom (public · main 브랜치가 라이브 배포본과 동일)

**바로 체험(설치 0)**: https://biocode67.github.io/modoo-bom/ — "72세 혼자 사는데 소득이 적어요" 입력.

**데스크탑 자동화 재현(Windows, 최초 5분)**:
```bat
git clone https://github.com/BioCode67/modoo-bom && cd modoo-bom
setup-local.bat        :: 경량 venv + 프론트 빌드 (최초 1회)
run-local-app.bat      :: localhost:8000 자동 오픈
```
→ 나의 복지 → 서류 도우미 상단 **[발급 전 점검]**(브라우저·정부24/복지로 연결 등 5항목 자동 점검)
→ **[🚀 전부 자동발급 + 자동신청까지]** 가 대회 핵심 장면: 정부24 서류 순차 발급(🔑 로그인 인증 1회 — 📱 승인만 본인)
→ 복지로 신청 양식 자동작성 + 방금 발급물 자동첨부 → **제출 직전 정지**(비가역 단계는 사람 몫 — 설계 원칙).

**품질 재현 명령**:
```bash
cd frontend && npm ci && npm run lint && npx tsc --noEmit && npm test   # vitest 1,415
cd ../backend && pip install -r requirements.txt && pytest tests/       # 231
cd ../frontend && npm run e2e:desktop                                   # 데스크탑 30종(에이전트 실행 중일 때)
```
자동테스트 1,812개(프론트 1,415·백엔드 397) · 실브라우저 E2E 12스위트(접근성 axe 위반 0 포함) · 재현 대본: `docs/청년월세-데모-시나리오.md`.
