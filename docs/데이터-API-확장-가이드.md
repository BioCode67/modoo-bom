# 데이터 API 확장 가이드 (7/19)

> 현재 카탈로그: 시드 190건(검증) + 한국사회보장정보원 B554287 약 5,143건 = 약 5,300건.
> 아래는 "여기서 더 늘릴 때" 가치가 큰 순서의 공공 API 추천과, 이미 구현해 둔 통합 방법.

---

## 1순위 — 보조금24 (구현 완료 ✅, 키만 넣으면 됨)

**행정안전부 '대한민국 공공서비스(혜택) 정보'** · data.go.kr **15113968**

- **왜 1순위**: 지금 카탈로그(B554287)는 '사회보장 복지서비스' 계열. 보조금24는 그 밖의
  **보조금·바우처·요금감면**(중앙 1,000+ 및 지자체·교육청 수혜서비스)을 덮는다 — 겹치지 않는 축.
- **통합 코드**: `backend/etl/ingest_gov24.py` (이번에 추가). 기존 카탈로그와 이름 디듑(기존 우선),
  지자체 소관은 LOC-(지역배지), 중앙은 GOV- 로 들어가 탐색·검색·엔진에 그대로 얹힌다.

### 사용 절차 (내 PC에서)
```bash
# ① data.go.kr 로그인 → '대한민국 공공서비스(혜택) 정보'(15113968) 활용신청(자동승인)
#    키는 기존 backend/.env 의 DATA_GO_KR_SERVICE_KEY 그대로 사용
cd backend

# ② 스키마 실측 확인(필수 — 응답 키 목록과 정규화 미리보기 출력)
python etl/ingest_gov24.py --probe

# ③ 수집 + policies.json 병합
python etl/ingest_gov24.py --run

# ④ 반영
cd ../frontend && npm run deploy        # 웹(gh-pages)
#   또는 npm run build:app              # 데스크탑앱
```
> ⚠️ 정직성 장치: 컨테이너(정부망 차단)에서 실제 응답을 못 봤기 때문에 필드 매핑은
> '후보 키 관용 매핑'으로 두었고, `--probe`가 실측 키를 보여준다. 후보에 없는 키가 보이면
> `ingest_gov24.py`의 `_CAND`에 한 줄 추가하면 된다(다른 코드 수정 불필요).

## 2순위 — 고용24/워크넷·HRD-Net (취업·훈련 축)

- **무엇**: 워크넷 채용정보 API + HRD-Net 직업훈련과정(국민내일배움카드) API (고용노동부, data.go.kr).
- **가치**: 국민취업지원제도·노인일자리 추천에 "지금 신청 가능한 훈련과정/일자리"를 실데이터로 연결
  → 추천이 제도 안내에서 **행동 가능한 다음 단계**로 이어짐.
- **비용**: 데이터 성격이 '정책'이 아니라 '공고'라 Policy 스키마가 아닌 별도 뷰가 필요(중간 규모 작업).

## 3순위 — LH 마이홈/임대주택 공고 (주거 축)

- **무엇**: LH·마이홈 임대주택 모집공고 API (국토교통부 계열).
- **가치**: HOU 시드 7건(정적)을 **살아있는 모집공고**로 대체 — 신청기한 배지·캘린더(.ics)와 시너지.
- **비용**: 공고 스키마 별도 + 마감 데이터 품질 관리 필요(중간 규모).
