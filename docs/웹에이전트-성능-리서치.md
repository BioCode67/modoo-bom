# 웹 에이전트/RPA 성능 리서치 — 상위 시스템 작동 방식과 모두봄 적용

> 목적: "openclaw"류를 포함한 상위 성능 웹 에이전트/RPA의 작동 방식을 조사·정리하고,
> 모두봄 RPA(정부24·복지로 등)에 **안전하고 정직하게** 적용해 성능(성공률·속도·복원력)을 올린다.
> (조사 2026-07-23. 개발환경은 정부 사이트 프록시 차단이라, 적용은 유닛/실Chromium/소스계약으로
> 잠그고 실동작은 팀원 실기기 확인으로 남긴다 — 없는 검증을 한 척하지 않는다.)

## 1) 벤치마크로 본 '지금 잘하는 것들'

| 벤치마크 | 무엇을 재나 | 상위 성적(2025~26) |
|---|---|---|
| **WebArena** | 셀프호스트 실사이트 812태스크(전자상거래·포럼·CMS·지도 등) | Claude 계열 ~68%, 특화 프레임워크(온라인 RL) 71~74%, 단일 에이전트 최고 ~61.7%(IBM CUGA) |
| **WebVoyager** | 실사이트 643태스크(검색·내비·폼·쇼핑) | 상위 상용 ~97-98%, 오픈소스 **browser-use ~89%**(OpenAI Operator 87% 상회) |
| **WebBench**(write류) | 폼작성·로그인·다운로드 등 RPA 핵심 | **Skyvern 64.4%**(write 태스크 특히 강함) |
| **Mind2Web** | 137개 실사이트 2,000+ 태스크 | 데이터셋(일반화 평가용) |

**시사점**: 우리와 가장 결이 같은 건 WebVoyager(실사이트 폼·내비)와 WebBench의 **write 태스크**
(폼작성·로그인·발급) — 여기서 강한 건 **browser-use**(접근성 트리+인덱싱)와 **Skyvern**(비전+검증+캐싱).

## 2) 상위 시스템의 작동 방식(핵심 메커니즘)

### A. browser-use (오픈소스 1위급, ~89% WebVoyager)
- **접근성 트리(a11y tree)를 '주' 컨텍스트**로 — 장식 마크업 제거, role·label·상호작용 요소만.
  raw DOM 대비 토큰 대폭 절약.
- **상호작용 요소 인덱싱(Set-of-Marks)** — 클릭 가능 요소에 안정적 숫자 ID → LLM은 **ID로** 행동.
- **비전은 선택적**(하이브리드) — 접근성 정보가 부실하거나 시각적일 때만.
- **ReAct 루프** — 관찰→계획→실행→점검→재계획.

### B. Skyvern (RPA 특화, WebBench 64.4%)
- **비전 LLM + 컴퓨터비전으로 요소 인식** — HTML 속성이 아니라 '보이는 모습'(색·모양·위치·문맥)으로
  버튼/폼을 식별 → 커스텀 셀렉터 없이 처음 보는 사이트도 동작, UI 변경에 강함.
- **Validator Agent(단계별 검증)** — 각 스텝이 실제로 됐는지 확인, 아니면 **백트랙/대안 시도**(복구).
- **⭐ Route Memorization / Code Caching** — AI가 한 번 성공한 경로를 **결정론 Playwright 스크립트로
  컴파일**해 다음부터는 LLM 없이 빠르고 일관되게 실행. 실패(페이지 변경)하면 에이전트가 깨어나
  '치유' 후 재컴파일. → **속도·비용·결정성**을 동시에 잡는 핵심 아이디어.

### C. Agent-E — **Change Observer(DOM diff)**
- 매 행동 뒤 **DOM 변화(diff)**를 관찰해 '기대한 변화가 생겼나' 확인 → 아니면 코스 수정.

### D. OSCAR — **Dual Grounding**
- 각 상호작용 요소에 **일관 ID + 서술 라벨(DOM)** + **이미지상 위치 표시** 이중 접지 →
  숨김/무라벨 버튼 혼동 감소.

### E. Reflexion / Self-Refine / CRITIC — **자기수정 루프**
- 행동 실패 시 **언어적 비평(critique)**으로 다음 시도 개선(trial-and-error).
- CRITIC은 **외부 검증 도구**로 근거 있는 자기수정(추측 아님).
- **에피소드 메모리**(실패→해결 쌍)를 저장해 새 문제에 재사용.

### F. BaRA — **규칙 기반 산출물 검증**
- 동적 DOM·팝업으로 인한 실패에 대비 + **산출물 검증**(URL 형식·환각 텍스트 여부)으로 '가짜 성공' 차단.

### G. 컴퓨터-유즈 에이전트 (OpenAI Operator/CUA, Anthropic Claude Computer Use, Amazon Nova Act)
- **행동→스크린샷→검증→반복 루프**: 스크린샷으로 상태 인지 → 다음 행동(클릭/타이핑) 결정 → 실행 →
  **다시 스크린샷 찍어 됐는지 확인** → 완료 또는 사람 입력 필요까지 반복. (CUA WebVoyager 87%·WebArena 58%)
- **비전 우선(픽셀 좌표)** + 추론. 웹 특화 태스크에서 강하지만 순수 비전은 그라운딩 정확도·비용이 약점.
- **Nova Act**: 작고 빠른 멀티모달 모델 + **신뢰성 중심** 설계(프로덕션 UI 워크플로용, 자격증명 보안 결합).

### H. 상용 RPA 자가치유 (UiPath Healing Agent, BrowserStack Self-Healing)
- **오류 분류**: 재시도 가능(timeout·element detached) → **wait-and-retry(3회, 지수 백오프)**;
  영구 오류(element not found·navigation blocked) → 재시도 안 함. **실패 스텝 ~67% 자가복구**.
- **백업 셀렉터 → 비전 폴백**: 저장해둔 대체 셀렉터 시도 → 안 되면 시각 검색으로 찾아 셀렉터 갱신.
- **팝업/오버레이 선(先)제거**: 대상을 가린 팝업의 '닫기/확인'을 찾아 치운 뒤 원 행동 재시도.
- **의도 기반(intent-driven) > 취약한 셀렉터**: "회원가입 완료" 같은 의도가 `#user_submit_btn` 보다 강건.

## 3) 공통 성공 요인 (5가지로 압축)

1. **의미 접지(Grounding)**: 접근성 이름 + role + (선택)위치로 요소를 사람처럼 지목. 첫 일치가 아니라 **점수화**.
2. **행동 후 검증(Act→Verify)**: 클릭/입력 뒤 '기대한 변화'(DOM diff·URL·마커·값)를 확인 — **가짜 성공 금지**.
3. **자기수정/재계획(Self-correct)**: 검증 실패 시 대안 전략으로 재시도(결정론→LLM→비전 에스컬레이션).
4. **경로 기억(Route memorization)**: 성공한 지목을 캐시해 다음엔 빠르고 결정론적으로, 실패 시 무효화·재학습.
5. **상태 안정 판단(Settle)**: 화면이 '가라앉을'(변화 멈춤) 때까지 대기 — 고정 시간이 아니라 상태로.

## 4) 모두봄에 이미 있는 것 (재발명 금지)

- **의미 접지 + 인덱싱 + ReAct**: `rpa/ai_fill.py`가 WAI-ARIA 접근성 이름 인지 + `data-modoobom-ai`
  요소 인덱싱 + 결정론→LLM→점검→재계획(2라운드) — browser-use 구조를 **폼 채움**에 이미 적용.
- **행동 후 값 검증**: `_do_fill`이 입력 후 '값 일치'를 지연 재검증(자기만족 검증 금지, 영타 오입력 차단).
- **산출물 검증**: 발급 성공을 genuine 신호(새 창·완료 텍스트·`%PDF-` 바이트·saved_path)로만 — '미발급을
  완료로 오보' 금지(honesty-first). BaRA식 산출물 검증과 정합.
- **상태 안정 판단**: `gov24_rpa._wait_document_rendered`가 픽셀 지문의 '멈춤'으로 캡처 시점 판단(시간 무관).
- **클릭 판단(신규)**: `ai_fill.ai_pick_action`이 클릭 가능 요소를 인덱싱해 목표 버튼을 결정론→LLM으로 지목.

## 5) 모두봄에 새로 적용한 것 (이번 작업, 안전·정직·Mock-safe)

1. **의미 접지 점수화**(OSCAR/browser-use): `ai_pick_action`이 '첫 일치'가 아니라 **정확일치>시작일치>부분
   일치 + role 가중**으로 후보를 점수화해 오클릭을 줄임.
2. **경로 기억**(Skyvern route memorization): `rpa/route_cache.py` — (사이트 host, 목표)별 **성공 라벨**을
   기억해 다음 실행에서 먼저 시도(빠름·일관). 클릭이 안 되면 무효화·재학습. **버튼 라벨만 저장**(입력값·
   개인정보 없음), 파일은 사용자 PC 로컬(gitignore). 키 불필요.
3. **자기수정 폴백**(Reflexion/Validator): gov24 문서출력 클릭이 하드코딩 라벨로 실패하면 `ai_pick_action`
   (결정론→LLM)으로 self-heal — 사이트 문구 변경에 자연 복구.
4. **자가치유 클릭**(UiPath Healing/BrowserStack): `_click_idx` 가 일시 실패(오버레이 가림·스크롤 밖·
   detached)에 ①일반→②화면에 들여 재클릭→③JS 합성 클릭(포인터 인터셉트 우회)로 단계적 재시도(지수
   백오프). 요소가 사라졌으면(영구 실패) 헛재시도하지 않는다.
5. **행동→검증→재시도 primitive**(CUA/Claude computer-use·Agent-E): `act_and_verify(do, verify)` +
   `page_signature(ctx)`(URL·요소수·본문길이 지문, PII 미포함) — '클릭은 됐지만 화면이 안 바뀜'을 잡아
   다음 후보로 자기수정. `ai_pick_action(verify=…)` opt-in(같은-페이지 진행에만; 새 창 여는 클릭 제외).

### 의도적으로 '안 한 것'과 이유(정직성/프라이버시)
- **발급물(등본 등) 화면을 비전 LLM에 보내 판정** — 그 화면은 실명·주민번호·주소를 담아 **PII 유출**이다.
  → 발급물 렌더 판정은 **로컬 결정론**(`_wait_document_rendered`)만 사용, 데이터가 브라우저 밖으로 안 나감.
- **행동 후 검증을 '새 창을 여는' 클릭(문서출력 등)에까지 일괄 강제** — 같은 페이지 시그니처가 안 변해
  '실패'로 오판→엉뚱한 버튼 연쇄 클릭 위험. 검증은 **같은 페이지 진행에 한해** 호출부가 명시적으로 쓴다.
- **완전 무인 제출·본인인증 자동화** — 설계상 금지(HITL 불변). 성능이 아니라 안전·법적 문제.

## 6) 다음 성능 레버(팀원 실기기 확인과 함께 검토)

- **DOM diff 기반 '진행 검증'을 같은-페이지 진행 클릭에 확대**(Agent-E) — 새 창 케이스는 제외 규칙과 함께.
- **에피소드 메모리**(실패→해결) — 흐름기록(`_flow/*.jsonl`)과 연계해 재발 실패의 자동 회피.
- **route_cache를 필드 채움에도 확장** — 성공한 (라벨→값키) 매핑 기억으로 결정론 계층 가속.
- 실사이트 실측이 되는 순간, 위 레버들의 실효를 흐름기록으로 측정해 우선순위화.
