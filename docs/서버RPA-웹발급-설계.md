# 서버 RPA — "웹만 열면 발급·신청" 설계 (2026-07-11)

> 사용자 방향 제시: 정부24 담당 유선 확인으로 자동화 접근이 허용됐으니, 설치 없이
> **웹에서 바로** 서버가 대신 발급·신청하게 하자. 개인정보는 서버에 저장하지 않는 방식으로.
> 결론: **코드는 이미 90% 준비돼 있고, 남은 건 한국 리전 서버 1대와 운영 결정.**

## 이미 만들어져 있는 것 (코드 재사용률이 높은 이유)

클라우드 백엔드(main.py)와 로컬 에이전트는 같은 RPA 코드를 쓴다. 원격 사용 전제로 설계된 부분:
- **진행 화면 스트리밍**: rpa-status가 단계 텍스트+스크린샷(시작자 토큰 인가)을 반환 → 웹 사용자가
  서버 브라우저의 진행을 실시간으로 본다(이미 프론트 폴링 UI 존재).
- **문서 회수**: rpa-file(토큰 인가·경로검사) → 사용자 브라우저로 PDF 다운로드.
- **다중 사용자 안전장치**: 동시 실행 상한(RPA_MAX_CONCURRENT)·대기 큐 백프레셔(can_accept→503,
  프론트 무설치 폴백)·태스크 타임아웃·진행중 보호 퇴거.
- **본인인증은 원래부터 원격**: 카카오/PASS 푸시는 '사용자 폰'으로 간다 — 서버가 어디 있든 동일.
- **인증수단 선택**(카카오·PASS·네이버·토스), 헤드리스 실측(정부24 헤드리스로 인증대기 도달 검증됨).

## 개인정보 무저장 설계 (이번에 코드로 추가·보강)

| 단계 | 처리 |
|---|---|
| 이름·생년월일·연락처 | 요청 → RPA 메모리에서만 사용, 로깅·디스크 기록 금지(rpa/config 원칙, 기존) |
| 발급 PDF | 서버 임시 저장 → 사용자 다운로드 '직후 자동 삭제' — **`RPA_DELETE_AFTER_DOWNLOAD=1`(신규, 테스트 고정)** |
| 진행 스크린샷 | 시작자 토큰(?t=) 없으면 응답에서 제거(기존) · 태스크 종료 시 메모리 퇴거 |
| 전송 구간 | HTTPS(플랫폼 TLS) · Cache-Control no-store |
| 잔여물 | 미다운로드 문서는 태스크 타임아웃/퇴거 주기에 맞춰 정리(운영 cron 권장: DOCS_DIR 1시간 초과 파일 삭제) |

## 반드시 확인해야 하는 것 (배포 전 실측 2가지)

1. **한국 IP 필수(추정 강함)**: 정부24·복지로는 해외 IP를 차단하는 경우가 많다. Render 무료(오리건)는
   불가 가능성 높음 → **한국 리전 서버**에서 `python -c "playwright로 plus.gov.kr 접속"` 첫 실측이 1순위.
2. **메모리**: 크로뮴 헤드리스 1개 ≈ 300~500MB. 동시 1~2명이면 **2GB램 VPS**가 안전선.

## 서버 옵션 (계정 소유자 결정 필요 — 비용)

| 옵션 | 비용 | 비고 |
|---|---|---|
| 네이버클라우드/가비아/iwinv 등 KR VPS 2GB | 월 1~2만원대 | IP 확실한 한국 · 권장 |
| AWS Lightsail 서울 2GB | $12/월 | 간단 |
| Render 유료 KR 미지원 | — | 리전 문제로 부적합 가능성 |
| (지금 당장) 데스크탑 앱 유지 | 0원 | 현행 — 서버 준비 전까지의 답 |

배포 절차(서버 확보 후): uvicorn main:app + `RPA_ENABLED=1 RPA_HEADLESS=1 RPA_DELETE_AFTER_DOWNLOAD=1
RPA_MAX_CONCURRENT=2` + playwright install chromium + 프론트 `VITE_API_BASE`를 이 서버로(또는 RPA 전용
베이스 분리). 대회 데모는 현행(로컬 앱) 유지, 서버 RPA는 확장 스토리로.

## LLM 시너지 (서버가 생기면 열리는 것)

- 이미 Render에서 LLM(Gemini) 챗이 돌고 있음 — 같은 서버로 합치면:
  ① 신청 양식의 '자유 서술' 칸을 LLM이 초안 작성(사용자 확인 후 입력)
  ② RPA가 막힌 화면(DOM 변경)을 LLM이 읽고 다음 행동 판단(자가 복구) — 기술적 하이라이트 후보
  ③ 발급 서류(PDF) 내용을 LLM이 읽어 신청 요건 자동 검증("소득금액증명의 금액이 기준 이하인지")
- 단 ②③은 PII가 LLM API로 나가는 문제 → 마스킹 후 전송 또는 온디바이스/자가호스팅 모델 검토(무저장 원칙 유지).

## 현장(복지관)과의 관계

- '다음 분 상담' 리셋은 **공유 기기 모드**의 장치 — 서버 RPA가 생겨도 각자 자기 폰으로 쓰는 일반
  사용자에겐 불필요(각자 브라우저=각자 저장소라 자연 격리). 두 모드는 공존한다.
- 월·화 현장은 현행 데스크탑 앱으로 진행(검증 완료). 서버 RPA는 그 다음 스텝.
