# 🖥️ 데스크탑 앱 재빌드 · 게시 가이드 (Windows)

> 최신 코드로 Windows exe/zip을 만들고, 라이브 사이트의 **[Windows 앱 바로 받기]** 버튼이
> 최신본을 내려주도록 GitHub Release를 갱신하는 순서입니다. **Windows PC에서만** 됩니다
> (PyInstaller가 Windows용 exe를 만들기 때문 — Linux/Mac에서는 불가).

---

## ⏱️ 3줄 요약 (이미 준비물·최초설정이 끝난 경우)

```bat
git checkout main && git pull
build-installer.bat
publish-release.bat
```

끝나면 앱 상단 상태 스트립의 **`v0.3.2 · 빌드 (오늘날짜) · (커밋)`** 로 최신본인지 확인.

---

## 🆕 새 PC(Windows)에서 아무것도 없이 처음부터

> Git도 없는 새 노트북 기준. **PowerShell**(시작 → "터미널" 또는 "PowerShell")에 그대로 붙여넣으세요.

```powershell
:: 1) 필수 프로그램 5개 설치 (winget — Windows 10/11 기본 내장)
winget install -e --id Git.Git --accept-package-agreements --accept-source-agreements
winget install -e --id Python.Python.3.11 --accept-package-agreements --accept-source-agreements
winget install -e --id OpenJS.NodeJS.LTS --accept-package-agreements --accept-source-agreements
winget install -e --id GitHub.cli --accept-package-agreements --accept-source-agreements
winget install -e --id JRSoftware.InnoSetup --accept-package-agreements --accept-source-agreements
```

**2) ⚠️ 터미널을 완전히 닫고 새로 여세요.** (방금 설치한 프로그램은 새 창부터 인식됩니다 — 이걸 안 하면 `git/python`을 못 찾아요.)

```powershell
:: 3) 설치 확인 — 4개 다 버전이 떠야 정상
git --version ; python --version ; node --version ; gh --version

:: 4) GitHub 로그인 (코드 받기 + 게시 인증을 한 번에 — 질문엔 엔터/기본값, 브라우저로 로그인)
gh auth login

:: 5) 코드 받기
gh repo clone BioCode67/modoo-bom
cd modoo-bom

:: 6) 최초 설정(첫 1회) → 7) 빌드 → 8) 게시
setup-local.bat
build-installer.bat
publish-release.bat
```

- `python`을 쳤는데 **Microsoft Store가 열리면**: 설정 → "앱 실행 별칭" → python.exe **끄기** 후 터미널 새로.
- 그다음부터는 `git pull` → `build-installer.bat` → `publish-release.bat` 세 줄만 반복하면 됩니다.

## A. 준비물 (첫 1회만 설치)

| 프로그램 | 용도 | 설치 |
|---|---|---|
| **Python 3.11+** | 백엔드·빌드 | https://python.org → 설치 시 **"Add Python to PATH" 체크** |
| **Node.js 20+** | 프론트 빌드 | https://nodejs.org (LTS) |
| **Git** | 코드 받기 | 이미 있음(저장소를 클론했다면) |
| **Inno Setup 6** | 설치용 .exe 생성 | `winget install JRSoftware.InnoSetup` — ⚠️ **없으면 ZIP만** 만들어짐 |
| **GitHub CLI** | 릴리스 자동 게시 | `winget install GitHub.cli` → 이후 `gh auth login` (한 번만) — 웹 업로드로 대체 가능(§D) |

> `winget`은 Windows 10/11에 기본 내장(없으면 Microsoft Store의 "앱 설치 관리자").

---

## B. 최초 설정 (첫 1회만)

```bat
:: 저장소 폴더에서
setup-local.bat        :: 경량 파이썬 환경(venv-local) + 브라우저 런타임 + 프론트 빌드 준비
gh auth login          :: GitHub 로그인(게시용) — 브라우저 인증, 한 번만
```

`setup-local.bat`이 `[오류] Python/Node 필요`라고 하면 위 A의 Python/Node를 먼저 설치하세요.

## C. 매번 재빌드 + 게시

### ⚡ 원클릭 (권장) — `update-and-publish.bat`

`git pull → build-installer.bat → publish-release.bat` 세 단계를 **중간 멈춤 없이 한 번에** 실행합니다.
**`update-and-publish.bat` 더블클릭**만 하면 최신 코드로 exe 를 새로 만들고 배포 웹사이트의
'앱 받기'(releases/latest)까지 갱신돼요.

```bat
update-and-publish.bat
```

- 세 단계 중 하나라도 실패하면 **그 지점에서 멈추고 이유를 보여줍니다**(무리한 진행 안 함).
- 사전 준비(첫 1회): `setup-local.bat` 실행 + `gh auth login`.
- ⚠️ **이 파일 자체는 처음엔 `git pull` 후 생깁니다** — 최초 1회만 수동으로 `git pull` 한 뒤부터
  더블클릭으로 쓰세요(이후엔 스크립트가 `git pull`부터 알아서 합니다).

### 수동 3단계 (원할 때)

```bat
:: 1) 최신 코드 받기
git checkout main
git pull

:: 2) exe/zip 빌드 (프론트 빌드 → PyInstaller → 패키징 스모크 자동 → ZIP → 설치 exe)
build-installer.bat

:: 3) GitHub Release 게시 (app-v0.3.2, --latest → 홈 CTA 자동 갱신)
publish-release.bat
```

- **`npm run e2e:exe`는 따로 돌리지 마세요.** 이 패키징 검사는 `build-installer.bat` 안에서
  올바른 환경으로 **이미 자동 실행**됩니다(따로 돌리면 경로가 달라 실패).
- 빌드 결과물은 `backend\dist\` 에 생깁니다:
  - `모두봄-에이전트.zip` — 압축 풀고 `모두봄-에이전트.exe` 더블클릭(Inno Setup 없어도 생성)
  - `모두봄-설치.exe` — 더블클릭 설치(**Inno Setup 있을 때만** 생성)

### 게시 후 확인
1. 시크릿(새) 창에서 https://biocode67.github.io/modoo-bom/ → 홈 하단 **[Windows 앱 바로 받기]**
2. 받은 파일 실행 → 앱이 열리면 **상단 상태 스트립**에 `v0.3.2 · 빌드 (오늘 날짜) · (커밋 7자리)` 표시
   → 날짜·커밋이 오늘 것이면 **최신본 반영 성공**. (구버전이면 예전 날짜가 뜹니다)

## C+. 다국어 AI 모델 동봉 (2026-08-11 신설 — 시연장 네트워크 대비)

시연장·기관망에서 HuggingFace/jsdelivr CDN이 차단·지연되면 다국어 의미검색이
"AI 모델을 불러오지 못했어요"로 죽는다(실측). 이를 막기 위해 **`npm run build:app`이
모델(~35MB)을 자동으로 받아 dist-app에 동봉**한다(`scripts/fetch-app-model.mjs`).

- **인터넷 되는 곳에서 빌드 1회** → `frontend/app-models/`에 캐시되고 dist-app/models/로 동봉
  → 이후 앱은 **오프라인·차단망에서도 다국어 검색이 동작**한다.
- 다운로드가 실패해도 빌드는 계속되고, 그 빌드는 기존처럼 CDN 폴백으로 동작한다
  (콘솔에 `⚠️ 필수 N건 실패 — 모델 동봉 없이` 경고가 뜨면 온라인에서 재빌드).
- 동봉 확인: 빌드 로그에 `dist-app/models 동봉 완료`가 보이면 성공.
  설치본 기준 `frontend/dist-app/models/Xenova/...`가 존재해야 한다.
- **결과 번역(Translator API)의 언어팩은 Chrome이 따로 받는다** — 시연 전 데모 PC에서
  영어·베트남어 질의를 한 번씩 실행해(언어팩 다운로드 유발) 리허설할 것.
  Chrome/Edge 138+ 필요(앱은 크롬을 우선 실행함).

## D. 자주 나는 문제

| 증상 | 해결 |
|---|---|
| `build-installer.bat`가 **"venv-local 없음"** | 먼저 `setup-local.bat` 실행(B단계) |
| **`모두봄-설치.exe`가 안 생김** / publish가 "설치.exe 없음" | Inno Setup 미설치 — `winget install JRSoftware.InnoSetup` 후 `build-installer.bat` 재실행 |
| `publish-release.bat`가 **gh 인증 오류** | `gh auth login` 실행(브라우저 인증). 또는 아래 웹 업로드 |
| **PC 보호(SmartScreen)** 파란 창 | [추가 정보] → [실행] — 미서명 오픈소스라 정상 |

### gh CLI 없이 웹으로 게시(대안 — 더 쉬움)
1. https://github.com/BioCode67/modoo-bom/releases → **Draft a new release**
2. Tag: `app-v0.3.2` · Target: `main` · **Set as latest release** 체크
3. `backend\dist\모두봄-에이전트.zip`, `모두봄-설치.exe`를 드래그 업로드하되,
   **파일 이름을 `ModooBom-Agent.zip` / `ModooBom-Setup.exe`로 바꿔서** 올리세요
   (GitHub이 한글 파일명을 지워 CTA 링크가 깨짐 — publish-release.bat은 이걸 자동으로 처리).
4. **Publish release**.

## E. ⚠️ 제출(구글드라이브)용과 라이브 CTA용은 별개

- **[필수] 제출물(드라이브)**: 위 §C-2의 **`모두봄-에이전트.zip`** 을 그대로 드라이브에 올리면 됩니다.
  (심사위원이 압축 풀고 `모두봄-에이전트.exe` 실행 → 데모 동작). **Inno Setup·gh 없이도 제출 가능** —
  ZIP만 있으면 됩니다. 게시(§C-3)는 라이브 사이트 버튼을 위한 것이라 제출 필수는 아닙니다.
- **[선택] 라이브 CTA**: §C-3(또는 §D 웹 업로드)까지 해야 라이브 사이트의 다운로드 버튼이 최신본을 내려줍니다.

> 즉, **시간이 급하면**: `git pull` → `build-installer.bat` → 나온 **ZIP을 드라이브에 업로드**면
> 제출은 끝. 라이브 버튼 갱신(게시)은 그다음에 여유 있게 하세요.
