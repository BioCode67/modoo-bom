# 복지로 RPA 실기기 검증 대기 체크리스트

> **왜 이 문서가 있나:** 개발환경에서는 실제 정부 사이트(정부24·복지로·대법원)가 프록시 차단이라
> 개발자가 실화면을 직접 볼 수 없다. 그래서 복지로 간편인증·자동신청 관련 변경은 **소스 계약 테스트 +
> 실Chromium 합성 e2e** 로만 잠그고, "실제 사이트에서 되는가"는 **팀원 실기기(PC) 확인**에 의존한다.
> 커밋 메시지의 **"(팀원 확인 요망)"** 표기가 그 대기 상태다. 이 문서는 그 표기가 유일한 추적이던 것을
> 한곳에 모아 **무엇을·어떻게 확인하고 → 어떤 상태인지**를 정직하게 관리하기 위한 것이다.

## 검증하는 방법 (공통)

1. **앱 실행**: `run-local-app.bat` 로 로컬 앱을 켠다 — 이때 흐름 기록(`RPA_FLOW_RECORD=1`)이 **자동으로**
   켜져, 자동화가 지나간 화면 구조가 `_flow/flow_YYYYMMDD.jsonl` 에 쌓인다(값 없음·PII 없음).
2. **해당 시나리오 실행**: 아래 표의 '확인 방법'대로 실제 복지로에서 자동발급/자동신청을 진행한다
   (📱 본인인증 승인·최종 제출은 항상 직접).
3. **결과 회수**: 화면 우측 상태 스트립의 **[🩺 진단 복사]**(_diag + 실패 화면 구조)와 **[🎬 흐름 기록 복사]**
   버튼으로 클립보드에 담아 개발자에게 전달. 실패했다면 그 화면 구조가 다음 수정의 근거가 된다.
4. **상태 갱신**: 확인되면 아래 표의 상태를 `✅ 확인`으로 바꾸고, 해당 커밋을 언급하는 후속 커밋에서
   **"(팀원 확인 요망)"** 표기를 더는 달지 않는다(이미 나간 표기는 지울 수 없으니 이 표가 진실 소스).

> ⚠️ 정직성: "확인"은 **실기기에서 실제로 성공을 관찰**했을 때만 표시한다. 코드 리뷰·합성 테스트 통과는
> "확인"이 아니다(그건 이미 각 커밋에서 통과). 검증 못 한 것을 검증한 척하지 않는다.
