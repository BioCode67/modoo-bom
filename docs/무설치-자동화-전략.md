# 확장 없이 "말하면 → 추천 → 인증만 하면 자동 발급·신청" — 전략과 로드맵

> 사용자 요구: 크롬 확장 설치·크롬 전용의 단점을 없애고, **웹/앱에서 바로** 상황을 말하고 →
> 혜택 추천 → 인증까지 자동 이동 → **사용자가 인증만 하면 자동 서류발급 → 허가 시 자동 신청**.
> 이 문서는 그게 기술적으로 무엇을 의미하는지 정직하게 정리하고, 실현 경로를 제시한다.

---

## 0. 왜 지금은 확장/로컬 에이전트가 필요한가 (기술적 벽)

정부24·복지로에서 실제 서류발급·신청을 하려면 **로그인된 브라우저 세션**을 조종해야 한다.
순수 웹페이지(우리 사이트의 JS)는 **다른 사이트의 로그인 세션을 조종할 수 없다**(브라우저 보안=동일출처정책).
게다가 정부24는 **안티매크로(Mbuster)** 로 자동화를 차단하고, **본인인증(카카오 간편인증)** 이 법적 필수다.

그래서 "실제 자동화"는 셋 중 하나가 반드시 필요하다:
1. **브라우저 확장** (지금 방식) — 설치 필요 + 크롬 전용.
2. **서버가 대신 브라우저를 띄움**(서버사이드 RPA) — 설치는 없어지지만 **위험**(아래 3안).
3. **정부 공식 API 레일**(마이데이터/전자증명서) — **안전·무설치·모든 기기**. 정답(아래 2안).

즉, "확장 없이 진짜 자동"의 정답은 **공식 API 레일**이다. 나머지는 편의성↔안전성의 트레이드오프.

---

## 1안 (지금 바로 — 이미 구현) · 무설치 "원터치 신청 이동"

설치 없이, 어떤 브라우저·폰에서도, **가장 매끄럽고 안전한** 경로. (오늘 배포)

- 흐름: 말/채팅으로 상황 입력 → 맞춤 추천 → **[신청] 한 번** →
  ① 내 정보(이름·생년월일·연락처)를 **클립보드에 자동 복사** →
  ② **공식 신청 페이지를 새 탭으로 즉시 열기**(딥링크) →
  ③ 사용자는 **정부 공식 사이트에서 간편인증(카카오)만** 하고 붙여넣어 제출.
- 장점: **무설치·전 브라우저·모바일 OK**, 개인정보·인증이 **정부 사이트에만** 머물러 안전, 법적 문제 없음.
- 한계: 최종 "발급·제출"의 마지막 클릭은 사용자가 함(완전 무인은 아님). — 하지만 대부분 사용자에겐 **충분히 쉽다**.
- 코드: `PolicyDetailDrawer.startApply`(복사+공식페이지 열기), `ApplyKit`(미리채움), `officialLinks.applyLink`(딥링크).

**모바일 강화(추가 가능, 저비용)**: 딥링크를 정부24·복지로 **앱 스킴**으로 열면(설치돼 있으면) 앱에서 네이티브 간편인증 → 더 매끄러움. 카카오 간편인증은 앱 내 원탭.

---

## 2안 (진짜 정답 · 사업 등록 필요) · 공공 마이데이터 + 공식 간편인증 API

**"인증만 하면 데이터·서류가 자동으로"의 공식 레일.** 브라우저 자동화가 아니라 **API로 정부↔우리 서비스가 직접** 주고받음.

- **공공 마이데이터(본인정보 요구권)**: 시민이 **한 번 동의**하면 행정정보(주민등록·소득·가족·건강보험 등)를
  정부가 **API로 직접** 우리 서비스에 전송. 스크래핑·안티봇 싸움 없음. 근거: 전자정부법(본인정보 제공요구권), 행정안전부 운영.
- **전자증명서 / 전자문서지갑(정부24)**: 등본 등 **전자증명서를 발급받아 기관에 유통**(문서 원본 그대로 제출) — API/중계로.
- **공식 간편인증**: 카카오·PASS·네이버·금융인증서 등 **전자서명인증사업자** 연동(간편인증 통합 SDK). 우리가 인증을 "대행"하지 않고, 사용자가 표준 인증 후 **결과 토큰**만 받음 → 안전.

**필요한 것(사용자=사업자 몫)**:
- **이용기관 등록**: 공공 마이데이터 이용기관 신청(행정안전부·한국지역정보개발원(KLID) 절차). 개인정보·보안 요건 심사.
- 간편인증 사업자 계약(월 이용료·건당 과금 있을 수 있음), 개인정보처리·ISMS 등 보안 준비.
- 리드타임: 수 주~수개월. **비용·심사 있음.** → 정확한 현행 절차·요건은 신청 포털에서 확인 필요.

**우리 코드 준비도**: 백엔드(FastAPI)에 `mydata` 연동 모듈만 추가하면 됨. 프론트는 "동의→인증→결과" UI만 얹으면 되고,
이미 프라이버시 우선(온디바이스) 설계라 마이데이터 원칙(최소수집·본인통제)과 정합.

> **권고: 이게 목적지다.** 출시 후 실사용/파트너십이 붙으면 2안으로 승격하면 "확장 없이 진짜 자동"이 완성된다.

## 3안 (기술적으로 가능하나 **비권장**) · 서버사이드 RPA(클라우드 브라우저)

서버가 헤드리스/실브라우저를 띄워 사용자 대신 로그인·발급. 설치는 없어지지만:
- **위험**: 우리 서버가 **로그인된 정부 세션 + 개인정보**를 쥐게 됨 → 명의도용·유출 책임. 우리 프로젝트의 **프라이버시·안전 원칙 위배**.
- **차단**: 정부24가 데이터센터 IP·헤드리스를 차단(Mbuster). 안정성 낮음.
- **결론**: 편의성은 높지만 **안전·정직성 원칙에 반해 채택하지 않음.**

---

## 4안 (배포 채널) · 네이티브/하이브리드 앱

- 크롬 확장 대신 **모바일 앱**(React Native/Expo 또는 웹뷰 래핑)으로 배포 → 앱스토어에서 바로 설치, 크롬 종속 제거.
- 앱은 카카오/PASS 간편인증 딥링크·복귀가 매끄럽고, 2안(마이데이터 API)의 **최적 그릇**이 됨.
- 현재 PWA(설치형)로도 상당 부분 대체 가능 — 앱스토어 정식 등록은 선택.

---

## 결론 · 추천 로드맵

| 단계 | 무엇 | 설치 | 안전 | 자동화 수준 | 상태 |
|---|---|---|---|---|---|
| **지금** | 1안 원터치 핸드오프 | ✅ 불필요 | ✅ | 인증·제출만 본인 | **구현·배포됨** |
| **다음** | 4안 PWA/앱 + 1안 모바일 딥링크 강화 | ✅ | ✅ | 동일(더 매끄러움) | 저비용, 바로 가능 |
| **목적지** | 2안 마이데이터/전자증명서 API | ✅ | ✅✅ | **인증만 하면 자동** | 사업자 등록 필요 |
| ~~대안~~ | ~~3안 서버 RPA~~ | ✅ | ❌ | 완전자동 | **비권장(위험)** |

**요약**: "확장 없이·크롬 없이·안전하게"의 정답은 **1안(지금 최선) → 2안 마이데이터(진짜 자동)**.
서버 RPA는 편하지만 안전을 포기하는 길이라 택하지 않는다. 사용자(사업자)가 **마이데이터 이용기관 등록**을
진행하기로 하면, 백엔드에 연동 모듈을 붙여 "인증 한 번으로 자동 발급·신청"을 공식적으로 완성할 수 있다.
