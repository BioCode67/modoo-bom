## 목표 1 — "다른 서류들도 제대로 자동발급"

현재 서류별 전용 폼 채움이 있는 것은 **소득금액증명(`_fill_income_cert_form`)·가족관계(efamily)** 뿐이고,
아래 9종은 **generic 채움**(`_select_doc_form_options` — 미선택 select만 첫 옵션으로)에 의존한다. 이들은
용도/발급목적 [검색] 팝업·귀속연도·세목 등 **서류별 필수 단계**가 있어 자동으로 못 넘어갈 가능성이 높다.

| 서류 | CappBizCD | 실측으로 확인할 것 |
|---|---|---|
| 지방세 납세증명서 | `13100000056` | 발급목적/용도 입력 방식(직접입력 vs [검색] 팝업), 사용목적 코드 |
| 지방세 세목별 과세증명서 | `13100000084` | 세목·귀속연도 select, 과세물건 선택 여부 |
| 국세 납세증명서 | `12100000011` | 사용용도·제출처 입력, 유효기간 |
| 기초생활수급자 증명서 | `14600000280` | 대상자·용도 select 유무 |
| 한부모가족 증명서 | `10601000001` | 대상자·용도 select 유무 |
| 출입국에 관한 사실증명 | `12700000024` | 발급대상·기간·용도 |
| 병적증명서 | `13000000016` | 용도·열람/발급 구분 |
| 건강보험료 납부확인서 | `SG4CADM2017` | 대상연도·기간 |
| 주민등록초본(옵션 많음) | `13100000015` | 포함 항목(과거주소·병역 등) 기본값 확인 |

### 실측 절차 (서류 1종당)
1. 데스크탑 앱에서 해당 서류 [자동] 발급 시작 → 로그인/간편인증 통과 후 **발급 폼에서 멈추는지** 확인.
2. 멈추면 카드에 이제 **"○○ 항목을 선택/입력해 주세요"**(위 P3 개선)가 뜬다 → 그 칸이 자동화 대상.
3. 브라우저 DevTools로 그 칸의 셀렉터·옵션값·[검색] 팝업 구조를 캡처(스크린샷 + DOM).
4. `_fill_income_cert_form`(`gov24_rpa.py:487`)을 본떠 **서류별 filler**를 추가하고,
   `gov24_rpa.py:1156` 부근 디스패치(`if "소득금액증명" in doc_name:`)에 조건 분기 추가.
5. 실발급 완주(PDF 저장)까지 확인한 뒤에만 커밋. 완주 전에는 β로 두거나 미등록.

> 참고: 완전히 새로운 서류(목록에 없는 것)를 늘릴 때는 앱 내 **[자동 확인]**(`probe.py`)로 CappBizCD를
> 실측 발굴하는 경로가 이미 있다. 위 9종은 이미 등록돼 있으니 **폼 채움**만 실측하면 된다.

## 목표 2 — 간편인증 구조 최적화

### 2-1. PASS 통신사(carrier) 자동 선택 — 가장 구체적인 공백
- **현상**: `routes.py`(≈266·545)에서 `carrier`(SKT/KT/LGU+)를 받아 `user_info`에 넣지만,
  `backend/rpa/` 전체에서 **한 번도 사용되지 않는다**(수집 후 버려짐).
- **영향**: 어르신 다수가 쓰는 **PASS(통신사)** 인증에서, 이미 받은 통신사를 매번 손으로 다시 골라야 함.
- **실측/작업**:
  1. 실제 PASS 위젯에서 통신사 타일/셀렉트의 셀렉터를 캡처.
  2. `base.py`에 `select_carrier(ctx, carrier)`(provider=="pass"일 때만 동작) 추가.
  3. 순수 정규화 `normalize_carrier("SKT"|"skt"|"에스케이"...)`는 브라우저 없이 유닛 테스트 가능 —
     이 부분만 먼저 [안전]으로 분리 가능.
- 위험도: 타일 클릭 = **실측 필요**, 정규화 함수 = 안전.

### 2-2. 두 개의 oacx 인증폼 자동채움 통합
- **현상**: 같은 anyid/oacx 위젯(`#oacx_name`·`#oacx_birth`·`#oacx_phone2`·`#totalAgree`)을
  gov24 `_autofill_auth_form`(`gov24_rpa.py:250`)과 nhis `_JS_FILL_FORM`(`nhis_rpa.py:87`)이
  **서로 다른 코드로** 채운다. 특히 **nhis는 휴대폰 앞자리(010) select를 설정, gov24는 안 함** — 한쪽 수정이
  다른 쪽에 반영되지 않는 드리프트.
- **작업**: `base.py`에 `fill_oacx_form(ctx, user_info)` 단일 헬퍼로 추출, 양쪽이 위임.
  단, 각 경로의 **현재 채우는 필드를 그대로 보존**(gov24에 앞자리 set을 새로 추가하는 것은 동작 변화 →
  별도 실측). 추출 자체는 목모드 테스트로 검증 가능하나, **실 위젯 회귀 확인이 필요**하므로 실측 후 반영 권장.
- 위험도: 방금(2026-07-20) 실측 검증된 인증 흐름과 얽혀 있어 **신중** — 실측 1회 필수.

### 2-3. nhis '인증 완료' 자동 클릭
- **현상**: `base.wait_for_login`(`base.py:673`)은 폰 승인 뒤 '인증 완료'를 자동 클릭하지만,
  nhis 전용 `_wait_login`(`nhis_rpa.py:310`)에는 없다. nhis 위젯이 그 클릭을 요구하면 승인 후 멈출 수 있음.
- **작업**: gov24 방식의 인증완료 자동 클릭을 nhis 대기 루프에 미러링(가드 포함).
- 위험도: nhis 위젯이 실제로 그 클릭을 요구하는지 **실측 필요**.

### 2-4. 제공자 값 경계 정규화 (안전, 선택)
- `routes.py`/`local_server.py`에서 `auth_provider`를 `AUTH_PROVIDERS` 키로 대소문자 무시 정규화하고
  첫 상태에 확정 제공자를 echo. 순수 입력 처리라 [안전]·패리티 테스트 가능.
