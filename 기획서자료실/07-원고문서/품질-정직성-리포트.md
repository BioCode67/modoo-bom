## 1. 우리가 푸는 문제 — 복지 사각지대

- 대한민국 복지는 **중앙부처·지자체·민간재단에 흩어져** 있고, 어렵게 쓰여 있으며, 신청이 복잡하다.
- 못 받는 이유는 자격이 없어서가 아니라 **몰라서, 어렵고 번거로워서**다.
- 모두봄 = 찾기(개인화 분석·의미 검색) → 이해(쉬운 말·용어사전) → 행동(서류·신청 자동화) → 사후관리(마감·갱신 챙김)의 **전 여정 에이전트**.

## 2. 정직성 원칙 (프로젝트의 뼈대)

AI 서비스가 가장 쉽게 무너지는 지점은 **과장**이다. 모두봄은 코드 수준에서 과장을 차단한다:

1. **환각 없는 AI**: 온디바이스 의미검색의 "AI 답변"은 검색결과 기반 규칙 템플릿 — 생성 모델이 지어내지 않는다.
2. **민간재단은 자격을 단정하지 않는다**: 심사·선발형이므로 엔진이 절대 '자격 충족'으로 표시하지 못하게 구조적으로 강제(테스트로 고정: `priority=low`, `confidence≤0.68`).
3. **금액 과장 금지**: 헤드라인 합산은 '현금성'만(바우처·대출·납입형 제외). "월 730만"류가 나올 수 없는 파서·필터.
4. **자동화 범위를 사실대로**: 본인인증·최종 제출은 사용자 몫(법적·비가역) — 화면·문서 모두 명시. 과거 가짜 상태를 만들던 result_tracker는 **제거**했다.
5. **소득 단위 구분**: '소득 하위 70%'(백분위)를 '중위소득 70%'로 오인해 기초연금 대상자를 배제하던 버그를 실측 앵커(2026 선정기준액)로 교정.
6. **없으면 없다고**: 무관한 검색어는 0건이 정답 — 억지 매칭 없음(골든 테스트로 고정).

## 6. 자동화의 정직한 경계 (심사 질문 대비)

- **되는 것**: 정부24 서류 13종 발급·복지로 신청을 크롬 확장이 사용자 브라우저 안에서 자동 진행(개인정보 서버 전송 0). 로그인 이동·양식 작성·발급/제출 직전까지.
- **안 되는 것(설계상)**: 카카오 본인인증·최종 제출 — 법적 요건이자 비가역 행위라 **사람이 하는 게 정답**(human-in-the-loop).
- 막히면: 화면이 정직하게 안내(30초 무응답 워치독 → "정부 탭에서 직접 눌러주세요" + 공식 링크 폴백).

## 7. 프라이버시

- 다국어 AI(임베딩 모델)는 **브라우저 안에서 실행** — 질의가 서버로 가지 않음.
- 자동화 개인정보(이름·생년월일·연락처)는 확장/로컬에서만 사용, 서버 전송·저장 0.
- 클라우드 백엔드는 RPA를 아예 실행하지 않음(`rpa:false`).
